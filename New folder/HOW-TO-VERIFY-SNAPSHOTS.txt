HOW TO VERIFY SNAPSHOTS — sample data walkthrough
=================================================

Two sets of sample workbooks were generated for this. Your real 4.5.1 data is
not involved and is never read by any of it.

    CellSens\Sandbox\          the September set — already in place
    _sandbox-october\          the October set — you copy these over, at step 4

`_sandbox-october` sits outside the CellSens folder on purpose: a release only
ever reads its own folder, so nothing there is picked up until you copy it in.


WHAT IS IN THE SANDBOX SET
--------------------------
Each file exercises something different:

  Regression_Test.xlsx     sections, a spec name filled once per group, and
                           one exact duplicate row -> 6 rows read from 7
  Acceptance_Test.xlsx     numeric measures (TC count, Pass, Fail)
  Feature_Test.xlsx        plain three-column list
  System_Test.xlsx         NO header row at all -> columns come out as
                           "Column 1 / 2 / 3" and no row is lost
  Unit_Test\part-a.xlsx    one testing type split across two workbooks
  Unit_Test\part-b.xlsx    -> combined into ONE snapshot, not two


THE WALKTHROUGH
---------------
1. In the app, open cellSens and use the Release menu -> New release.
   Name it exactly:  Sandbox
   Leave the folder blank — it derives to CellSens\Sandbox on its own.
   Untick "Make this the current release" if you would rather 4.5.1 stays
   the one that opens by default.

2. Press "Load from Excel", leave the period as September 2026, and create
   the snapshot. Expect:

     Acceptance Testing   #1   4 records
     Feature Testing      #1   3 records
     Regression Testing   #1   6 records read from 7, 1 duplicate skipped
     System Testing       #1   3 records
     Unit Testing         #1   4 records   <- from BOTH part-a and part-b

   Unit Testing is flagged as a conflict because two workbooks match it. The
   dialog ticks both; leave them ticked and they are combined into one
   snapshot. Untick one to load only that half.

3. Press "Load from Excel" again without changing anything. Every testing
   type reports:

     No change since snapshot #1.

   Nothing is written. Re-loading unchanged data can never create a duplicate
   snapshot, because the check hashes the parsed contents, not the file bytes.

4. Copy everything from  _sandbox-october\  over  CellSens\Sandbox\
   (overwrite when asked), then load again with the period set to
   October 2026. Expect:

     Acceptance Testing   #2   5 records   +1 added, 1 changed
     Feature Testing      #2   3 records   not comparable (columns changed)
     Regression Testing   #2   6 records   +1 added, 1 changed, 1 removed
     System Testing       #2   4 records   +2 added, 1 removed
     Unit Testing         #2   5 records   +1 added

   What each one is showing you:

   - Regression: a count changed (Exposure Table 40 -> 55), a row was added
     (Frame Rate), and a row was deleted from the sheet (Stage). The current
     snapshot drops the deleted row; snapshot #1 still has it.

   - Feature: October added an "Owner" column, so the columns that identify a
     row changed. Rather than claim 3 removed and 3 added, the diff says it
     cannot be compared. Both snapshots still render with their own columns.

   - System: the date on FL-6002 changed. Because that sheet has no numeric
     columns, every column is part of a row's identity — so a changed date
     reads as one row removed and one added, not as a change. That is the
     identity limitation, visible in real data.

5. Open the History tab on any testing type. You should see both snapshots,
   newest first, with a bar per snapshot. Click "Open" on #1 — the page shows
   September's data behind a banner saying it is history, with "Back to
   current" to return.

6. Try deleting a snapshot: History -> the bin icon on #2 -> confirm. #1
   becomes current again and its records come back. Load once more and the
   corrected data goes in as a fresh snapshot.


CLEANING UP
-----------
Delete the Sandbox release from the Release menu — that removes its snapshots
and rows, and nothing else. Then delete the CellSens\Sandbox and
_sandbox-october folders if you want the files gone too.
